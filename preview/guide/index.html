GUIDE · GJ B2B PC DESIGN SKILL

Skill 使用指南

把这套 Skill 作为 AI 的设计依据，用同一套 Token、组件契约、图标与页面模式生成或检查 PC 端 B 类项目界面。它负责设计规则与原型表达，不替代真实前端组件库。

01 · WHAT

先明确它是什么

Skill 是给 AI 读取的设计系统资源包。使用时要区分设计依据、人工预览和真实工程实现的边界。

AI 的设计依据

SKILL.md 负责路由，references/ 保存规则、契约与 Token，assets/ 保存可复用资源。

人工验收站

preview/ 用于浏览组件、交互和页面模式，不是生成时的设计真值，也不是生产组件源码。

前端映射依据

Skill 可以输出结构与高保真原型，但真实组件 API、事件、无障碍和发布版本仍由前端组件库确定。

04 · PROMPTS

常用 Prompt 示例

复制后替换方括号中的业务信息。明确点名 SKILL.md、页面模式或组件，可以显著减少 AI 凭经验自由发挥。

生成新页面

从页面模式开始

参考这套 Skill 根目录的 SKILL.md，生成一个「[页面名称]」PC 端 B 类页面，使用「[查询列表 / 表单填写 / 对象详情 / 工作台 / 分步任务]」模式，核心任务是「[任务]」。实现前先输出《本页用料清单》，业务信息不清楚的部分标记“待确认”，不要自行补造。

检查已有页面

只审查，先不修改

请对照 SKILL.md 的“页面生成组件门禁”和 references/generation-verification.md，检查「[页面文件路径]」。重点找出原生 CSS 重画已有组件、页面私有样式覆盖组件状态、组件尺寸混用、图标颜色不一致、溢出和响应式问题。先列问题与依据，不直接修改。

组件选型

只查规则，不生成代码

这套设计系统里，「[业务场景]」应该使用哪个组件？请从 coverage 和 components/inventory.json 开始查询，说明推荐组件、默认尺寸、适用状态、交互边界、需要的图标与 Token。先不要写代码；如果组件尚未完成 Figma 审计，请明确说明。

生成后验证

要求真实渲染实测

页面完成后，请按 references/generation-verification.md 做真实浏览器渲染验证，至少覆盖 1440px、1280px 和该模式要求的窄宽度。检查内容溢出、组件尺寸、图标与文字同色、间距阶梯、浮层开合、键盘交互和唯一运行时，并汇报发现与修复结果。

05 · CHECK

交付前验收

以下六项是最容易出错、也最值得优先检查的生成质量门槛。

组件来源可追溯
页面中的组件、图标和关键颜色都能对应到 schema、manifest 或语义 Token。
没有原生 CSS 重画
已有组件必须使用共享 gj-* 基座；页面 CSS 只处理布局、宽度和间距。
状态和交互闭环
实际触发 Hover、Focus、Pressed、Disabled、Selected、Loading、Error 与浮层关闭。
尺寸与颜色准确
同组控件尺寸一致；按钮 Icon 使用 currentColor，并随文字同步变化。
响应式不改变组件
断点只负责栅格换列、模块堆叠和局部滚动，不缩放组件或改变页面边距策略。
真实渲染通过
至少实测 1440px 与 1280px，无溢出、遮挡、异常空白、重复 DOM 或重复监听。
