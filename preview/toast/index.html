操作反馈类型组件 · Feedback

轻提示 Toast

用于反馈操作结果、系统状态或轻量提醒。Toast 不阻断当前任务，应在操作后即时出现，并用一句明确文案说明对象与结果。

外观类型

根据反馈场景选择容器，而不是仅按视觉偏好切换。静态样本使用真实 Toast 组件，不带视口定位。

Float 浮层型

顶部居中
保存成功

白色容器配合浮层阴影，用于保存、提交、复制等全局操作结果。

Transparent 语义背景型

顶部居中
请检查未填写的内容

浅语义色强化状态区分；Loading 保持中性白底，不套用语义浅底。

Black 黑底型

底部居中
已复制

内容自适应且不提供关闭按钮，适合浏览、预览和复制后的即时提示。

状态语义

状态图标、颜色和文案必须一致。Transparent 与 Float 共用五种状态，Black 只区分有无信息图标。

交互演示

验证外观、状态、关闭入口、自动消失、连续堆叠和 Loading 原位更新；同屏最多保留 3 条。

Toast 视口层Float / Transparent 距顶部 24px
Black 距底部 24px

属性控制

控制项使用组件库 Medium 输入、选择、复选框与按钮。

最近事件：尚未操作

结构与规格

尺寸直接引用 Toast 组件 Token；业务页不得复制规范页的舞台、卡片或定位辅助样式。

选用与行为规则

优先保证结果明确、出现及时、消失可控；需要用户决策或长期保留时切换到更合适的反馈组件。

显示时长

成功 2–3s · 信息 3s · 警告/失败 4–5s

Loading 不自动消失；较长信息、警告与失败应保留关闭入口。

Loading 原位更新

加载 → 成功 / 失败

处理结束后替换原 Toast，不另外叠加一条结果提示。

文案

对象 + 结果 / 当前进度

推荐“保存成功”“报告导出中，请稍候”，避免“系统提示”等空泛表达。

组件边界

非阻断、无需立即决策

确认决策用 Modal；持久通知或多操作用 Notification；表单错误就地展示。

可访问播报

status / polite；紧急失败才用 alert

不只依赖颜色，必须同时保留状态图标和明确文案。

暂停与动效

Hover / Focus 暂停计时

关闭按钮提供可访问名称，并响应 prefers-reduced-motion。
