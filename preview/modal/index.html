操作反馈类型组件 · Feedback

弹窗 Modal

用于承载需要用户集中处理、确认或完成的单一任务。Modal 会暂时中断当前流程，适合重要确认、表单录入和具有明确下一步操作的内容。

组件结构

Modal 只定义标题栏、关闭入口、内容插槽和底部操作区；确认、表单和复杂选择均作为内容配方插入。

弹窗标题
业务内容区域 / Content Slot
内容从左侧起排、撑满插槽，高度按任务自适应。

Header

高 64px · 水平 20px

标题 16/24、600；左对齐，不承载副标题或多级导航。

Close

图标 20px · 热区 32px

Hover 只改变图标颜色；Pressed 使用轻背景，Focus 保留焦点环。

Content

无默认内边距 · 仅内容区滚动

业务配方自行决定内边距，所有内容左对齐并撑满可用宽度。

Footer

高 76px · gap 8px

按钮 Medium、右对齐，次操作在左，唯一主操作在右。

内容配方

组件外壳保持 Standard；确认、危险、成功、错误及表单差异由内容插槽内的标准组件组合表达。

表单内容

表单控件统一使用 Medium，标签和控件从左侧起排，不把控件栏挤向视觉中心。

尺寸与结构

以满足内容的最小档位为准；Medium 是桌面端默认，不允许用更大尺寸补偿内容过少。

尺寸容器宽度推荐场景结构规则
Small400px简短确认、单项提示、结果反馈内容简短；不通过增大弹窗制造留白
Medium600px默认表单、常规信息确认桌面端默认尺寸；内容左对齐撑满
Large800px复杂选择、多区域或高密度内容高度超限时只滚动 Content

选用与行为规则

Modal 是阻断型任务容器，重点是明确任务、控制焦点并保护未保存内容，而不是承载所有反馈。

单一任务

一个 Modal 只处理一个目标

不堆叠无关内容、复杂导航，也不在弹窗中再次打开弹窗。

关闭方式

Close · Cancel · Escape

包含未保存内容时，关闭、Escape 与遮罩关闭都必须先确认。

焦点管理

进入、限制、恢复

打开后焦点进入弹窗，Tab 限制在内部，关闭后返回触发元素。

内容滚动

固定 Header / Footer

弹窗不得超出视口；内容过长时只滚动 Content 区域。

操作优先级

唯一主操作 + 明确动词

使用“提交”“删除”“保存”；危险操作说明不可逆后果并使用错误色。

组件边界

不要升级轻量反馈

即时结果用 Toast，非阻断长期信息用 Notification。
