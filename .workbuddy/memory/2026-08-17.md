## 13:56 — 复制/下载功能彻底重写
- **问题**：用户反馈弹窗三个按钮（复制SVG/下载SVG/下载PNG）功能完全不工作
- **根因分析**：fetch() 在 iframe 内可能因 Promise 链断裂导致静默失败；toast z-index 未设置被 modal-mask(z-index:1000) 遮挡；toast 用 position:fixed 在 iframe 内定位到页面底部而非视口底部
- **重写方案**：
  - 用 XMLHttpRequest 替代 fetch()，带 timeout/onerror/onload 完整错误处理
  - 复制用 execCommand('copy') 为主（不依赖 clipboard 权限），clipboard API 为降级；最终降级为弹出 textarea 供手动复制
  - 下载用 createObjectURL + `<a download>` + click()，元素不设 display:none 而是 1px 透明
  - 添加全局 window.onerror 捕获器，错误会显示在 toast
  - 按钮 loading 状态（"复制中..."/"下载中..."）+ disabled 防重复点击
  - toast 改 position:absolute + 动态计算 top（parent.scrollY + innerHeight - 60），z-index:2000
  - iframe allow 属性修正为 `allow="clipboard-write"`（移除无效的 downloads 指令）

## 14:07 — 复制/下载功能最终修复（嵌入内容方案）
- **问题**：之前用 XHR/fetch 从服务器获取 SVG/JSON 内容，但页面通过 `file://` 协议打开时浏览器禁止所有 XHR 请求，导致"获取文件失败"/"下载失败"
- **根因**：`<img>` 标签可以通过 file:// 加载本地文件，但 `XMLHttpRequest` 和 `fetch()` 被浏览器安全策略阻止
- **解决方案**：将全部 SVG（440 个）和 Lottie JSON（4 个）内容直接嵌入 JS 文件 `assets/icons/icon-content.js`（815KB），页面加载时一并读入内存
  - 生成 `window.SVG_CONTENT` 对象：键=文件名（如 `icf_system_bell-fill.svg`），值=SVG 源码字符串
  - 生成 `window.JSON_CONTENT` 对象：键=文件名（如 `loading_line.json`），值=JSON 字符串
  - 复制 SVG/JSON：直接从内存对象取内容，`doCopy()` 复制到剪贴板，无需网络请求
  - 下载 SVG/JSON：`doDownloadText()` 从字符串创建 Blob 再下载，无需网络请求
  - 下载 PNG：用 `<canvas>` 从已加载的 `modalImg` 提取图片数据，`canvas.toBlob()` 导出 PNG，无需网络请求
- 验证：440 个 SVG 文件名无冲突，可安全用 basename 作为键
- iframe 版本号 v14→v15
