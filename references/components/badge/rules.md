# Badge 徽标

> 从 `references/design-system-rules.md` 拆分（2026-09-08）。跨组件的颜色/字体/布局/圆角等基础规范见该文件“基础规范”章节。

- 依附通知图标、头像或文字右上角，用于提醒或计数，不替代完整状态说明。
- Dot 为 8px、无描边；Number 高 24/20/16（M/S/XS），字体 S8/S9/S10；Badge_status 为圆点+文案，间距 8px。
- 数量为 0 时隐藏。封顶值由业务设置，常用 99+ 或 999+，同一项目保持稳定；超出显示“封顶值+”。
- Dot 只表达存在新状态；需要数量时使用 Number。颜色引用对应语义 Token，不使用装饰性色。
- Badge 固定依附对象右上角，不漂浮至相邻元素；同一对象不同时叠加 Dot 和 Number。


- 实现基座：`assets/styles/gj-b2b-components.css` 的 `.gj-badge*` 共享类（2026-09-09 从预览页内联样式提炼），对应结构/颜色 Token 见 `assets/styles/gj-b2b-tokens.css` 的 `--ds-component-badge-*`；宿主元素使用贴边 Dot/Count 时需自带 `position:relative`。

## 2026-09-14：用户确认的真实使用场景清单（Badge vs Tag 边界）

用户在推进模式页组件覆盖时给出的完整场景清单，作为 Badge 该不该用、Tag 该不该用的权威依据，后续生成/审查页面时必须对照本节，不能凭感觉挑组件。

### 一、未读 / 未处理数量（Badge：Number 或 Dot）

| 场景 | 形式 | 说明 |
|---|---|---|
| 消息图标 | 数字 | 提示有几条未读消息 |
| 通知铃铛 | 红点或数字 | 有新通知 |
| 邮件/站内信 | 数字 | 未读数量 |
| 待办事项 | 数字 | 待处理任务数 |
| 日历组件内待办事项 | 红点+待办类型 | 日历组件里已有规定，按 `references/components/date-picker/` 现有约定执行，不在本节重复定义 |

### 二、状态标记

| 场景 | 形式 | 说明 |
|---|---|---|
| 任务状态 | 圆点状态徽标（Badge_status）：待开始 / 进行中 / 暂停 / 任务完成 / 已逾期 | 颜色圆点 + 文字区分状态 |
| 内容状态 | Tag 标签：草稿 / 审核中 / 已发布 | 后台内容管理场景，用 Tag 不用 Badge |
| 用户状态 | 圆点状态徽标：在职 / 已离职 | 后台用户管理场景 |

要点：状态 Badge 通常用语义色——绿=成功/在线，红=错误/紧急，黄=警告/待处理，灰=中性/禁用。

### 三、分类 / 标签（优先用 Tag，不用 Badge）

给内容打分类标记、帮助用户快速识别类型时优先用 Tag，例如：资产类别（A股、ETF、场外基金、指数、固收）、资讯类别（新闻速递、热点解读、隔夜新闻）、文件权限（私有、公开）。

### 四、入口 / 功能标记（Badge，且要克制）

| 场景 | 形式 | 说明 |
|---|---|---|
| 顶部导航栏通知/邮件 icon | 红点/数字 | 该 Tab/icon 下有未读内容 |
| 侧边菜单 | 数字 | 该模块有待处理事项 |
| 新功能入口 | New | 引导用户尝试 |
| 限时活动 | Hot / 限时 | 营销入口 |

要点：导航上的 Badge 要克制，到处挂红点会让用户麻木，反而失去提示作用。

### 五、头像 / 用户相关

| 场景 | 形式 | 说明 |
|---|---|---|
| 在线状态 | 圆点状态徽标 | 在线/离线/忙碌 |
| 消息提示 | 头像右上角数字/圆点 | 该用户有未读消息/发来消息 |

### 六、不适用场景（禁止用 Badge 的地方）

| 场景 | 原因 |
|---|---|
| 需要用户立即处理的重要信息 | Badge 太轻，容易被忽略，应改用弹窗、横幅或通知（Modal/Alert/Notification） |
| 复杂信息 | Badge 只适合极短文本或数字，长文本应改用 Tag 或卡片 |
| 同一区域大量 Badge | 视觉噪音，用户无法聚焦 |
| 操作按钮上 | 会干扰按钮本身的识别，除非未来有特殊场景需求 |
| 纯装饰 | Badge 有信息含义，不应仅为了好看而加 |
