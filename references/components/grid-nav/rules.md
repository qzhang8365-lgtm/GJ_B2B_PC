# GridNav 宫格导航

> 从 `references/design-system-rules.md` 拆分（2026-09-08）。跨组件的颜色/字体/布局/圆角等基础规范见该文件“基础规范”章节。

#### 用途与结构

- GridNav 用于聚合一组平级的快捷功能入口，适用于首页功能区、常用功能、推荐功能、多业务入口和卡片式工作台。
- GridNav 是局部快捷导航，不代替 Navbar、Sidebar 或产品的主信息架构。
- 单项 `GridNav-item` 由图标、标题和整项点击区域组成，可选叠加圆点 Badge 或数字 Badge。
- 每个入口必须指向明确功能、页面或任务；不把纯状态信息、不可操作说明或不同层级的父子入口混在同一宫格中。

#### 属性与枚举

- `grid`：`4*1 / 5*1 / 4*2 / 5*2`（Figma 母版 `2942:532`）。
- `items`：按视觉顺序排列的入口集合，实际显示数量不得超过当前 Grid 容量。
- 单项属性：
  - `icon`：必填，使用已维护的图标资产；Figma 槽为 `Placeholder/placeholder` 36×36 可替换实例。
  - `text`：必填，入口标题。
  - `badge`：`none / dot / number`。对应 Figma `GridNav-item` 的 `badge` × `number_badge` 布尔轴：`none` = 双 false，`dot` = 仅 badge true，`number` = 双 true。未发布 `badge=false, number_badge=true`。
  - `badgeValue`：数字 Badge 的显示值。
  - `disabled`：仅在入口暂时不可用且仍需保留位置时使用。Figma 无 Disabled 轴；运行时整项 `opacity: 50%` 且不可点。
- 同一项不可同时展示圆点 Badge 和数字 Badge。
- 2026-09-09 确认：Figma 带 badge / `number_badge` 的 GridNav-item 只给设计师看。代码侧组合 Badge 组件，并按 Badge 的位置规则锚在图标槽右上角；不把设计师母版里的徽标图层当作实现真值，也不从 GridNav 预览私有 CSS 反推徽标尺寸。

#### 尺寸与布局

- 单项 68×70px（垂直 padding 4、图标 36、图文距 8、标题行高 18）。图标槽圆角 8px（已绑定 `Radius/Radius-MD`）。2026-09-09 曾把填充改绑 `Background/Secondary`（Figma variable_defs 真值），但 2026-09-11 发现与 Glass Icon 的既有规则冲突（见 `components/icon/rules.md`「Effect Icon / Glass Icon」与 `design-system-rules.md` Glass 章节：这批图标烘焙时固定假设“干净的白色背景”，GridNav 被点名为目标场景之一），圆角方槽的纯色底在 Glass Icon 半透明/圆润边缘外会露出一圈可见的浅灰色描边（GNV-007）。GridNav 目前接入的图标资产 100% 是 Glass Icon，因此图标槽默认改为透明，不再叠加 `Background/Secondary`；圆角保留但默认不可见。若后续业务改用不透明的线性/填充图标且视觉上需要一块底色，使用可选修饰类 `gj-gridnav-icon-wrap-tinted` 单独开启该填充，不作为默认行为。
- 图标与标题垂直排列、居中；标题区域宽 68px。
- 列间距 12px（`Interval/space4`）；双行行间距 8px（`Interval/space3`）。
- hug 宽：4 列 308px，5 列 388px；双行高 148px。这是内容撑开结果，不是强制 min-width。
- 规范说明画板里的 5×2 实例 `2976:765` 被挤到 372px、列距变成 8px，**不要抄进实现**。
- 4 列和 5 列是组件预设，不通过任意缩窄单项宽度强行增加列数。
- GridNav 在容器中应保持完整、等宽和清楚的列对齐；容器不足时优先切换列数或调整外层布局，不裁切末列。

#### 图标规则

- AI 生成 GridNav 时优先从已上传的 Glass/Effect Icon 中选择合适资源，但这不是强制的唯一图标类型。
- 具体业务可根据产品定位、场景需求新增图标设计或进行个性化定制；新增资产仍需遵守图标命名、画布、格式和管理规则。
- 同一组图标应保持统一的视觉语言；如需混用 Glass Icon、普通线性 Icon、填充 Icon 或个性化图标，必须有明确的业务或视觉理由，并由具体设计稿确认。
- 图标只表达入口识别，不重复在图标内部嵌入标题文字。
- 图标加载失败时不得显示破损图片；应使用统一的缺省资源或隐藏该无效入口，并记录资产错误。

#### 标题与省略

- 标题文字样式为 `中文/S9-CN-R`（12/18/400），颜色 `Text/Secondary`。
- 标题使用简短的名词或动宾短语，建议不超过 6 个中文字符，保持单行。Figma 示例文案「最多6个字…」本身已带省略号；真实超长标题仍须 CSS 单行省略。
- 超出标题区域时使用单行省略，不换行破坏宫格行高。
- 省略标题在 Hover 或键盘聚焦时通过 Tooltip 显示完整名称。
- 同组入口命名采用一致语法，不混用产品全称、随意简称和完整描述句。

#### Badge

- `dot` 只提示“存在新内容或待关注变化”，不表达具体数量。
- `number` 用于数量对用户判断入口优先级确有帮助的情况，不作为装饰。
- 数字 Badge 必须设置明确的显示上限；上限值由具体项目或组件配置确定，超过上限时使用“上限值+”形式，例如上限为 99 时显示 `99+`。
- 项目未指定上限时可默认采用 99，但 AI 不得假设所有业务都固定使用 99。
- Badge 固定在图标右上角，不挤压图标或标题，不改变单项占位尺寸。尺寸与颜色引用 Badge 组件，不在 GridNav Token 中复制。
- Badge 颜色应使用提醒或错误等已定义语义色，不直接使用临时 HEX。
- 数据归零后隐藏 Badge，不展示数字 0 的提醒角标。

#### 状态与交互

- 整个 GridNav-item 是一个点击目标，不要求用户精确点击图标或文字。
- Default：透明项底 + `Background/Secondary` 图标槽 + `Text/Secondary` 标题。Figma 不另发状态轴。
- Hover：代码使用 `Background/Hover`，已写入组件 Token；不移动图标位置。不是 Figma variant。
- Focus：键盘聚焦必须可见，并覆盖完整点击区域（无障碍补充，非 Figma 轴）。
- Disabled：Figma 不发布轴。不可点击、不可触发 Hover；仅在保留位置有助于理解功能结构时出现，整项透明度 50%。
- 因权限不足而不可用的入口可以隐藏，也可以保留为 Disabled，最终方案由具体项目的权限策略决定。
- 如果 PRD 提到权限管理但未说明无权限入口是否可见，AI 必须向使用者确认，不得自行决定隐藏或展示。
- 入口点击后的跳转、打开新窗口或执行业务操作应符合该入口真实任务，不能只提供装饰性点击反馈。

#### 数量、分类与溢出

- 单个组件预设最多展示 10 个入口，即 `5*2`；不得无限增加行数造成页面持续向下堆叠。
- 少于容量时按既定视觉顺序从左到右、从上到下排列，不用空白占位伪造入口。
- 入口超过单组容量时，优先按稳定的业务分类拆分，并使用 Tabs 切换不同分组。
- Tabs 只切换平级入口集合，不把不同权限层级或父子业务结构伪装为分类。
- 如果入口数量长期庞大或分类复杂，应改用 Sidebar、完整功能目录或独立导航页，而不是继续扩展 GridNav。

#### 排序与一致性

- 常用入口优先按使用频率和任务重要度排序；推荐入口应有明确推荐逻辑。
- 同一产品内入口位置应保持稳定，避免每次刷新无依据重排，破坏用户空间记忆。
- Badge 更新、权限变化或临时不可用不应自动改变其余入口顺序。
- 具体业务设计稿可替换图标和标题，但必须保持 GridNav 的尺寸、对齐、状态与点击边界规则。
