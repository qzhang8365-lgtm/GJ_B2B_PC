# Carousel 走马灯

> Figma 真审计：页面 `2638:1007`，2026-09-09。结构化证据见同目录 schema、mapping 与 audit。

- Carousel 用于一组同层级内容的顺序浏览，不用于承载必须同时比较的信息；重要信息不能只依赖自动轮播曝光。
- Figma 主组件 385×160、底部 padding 12；指示器支持 bottom_center、bottom_right、bottom_left，默认居中。
- 指示器 active 条为 16×3，inactive 条为 8×3，间距 3、圆角 4。Light 使用 `Text/reversal` / `Background/WT_20`，Dark 使用 `Text/blue` / `Background/MK_20`。
- `Direction=Direction3` 实际是 Dark 主题，`.dot` 的 `ture` 是拼写错误；生成层只使用 `indicatorTheme=dark` 与 `active:boolean`。
- 默认不自动播放；业务确需自动播放时，间隔不得短于 3 秒，悬停、焦点进入、页面不可见和减少动态效果设置下必须暂停。
- 支持左右方向键、指示器点击与触屏滑动。指示器的视觉条只有 3px 高，但点击目标至少 24×24。
- 当前 slide 必须可感知并可操作；其他 slide 从 Tab 顺序与辅助技术中隐藏。主动切换时播报“第 x 项，共 n 项”，自动轮播不反复播报。
- `loop=false` 在首尾停止；`loop=true` 首尾连续。少于两项时隐藏指示器和所有切换行为。
- Figma 已发布原生箭头组件 `Carousel_item_arrows`（2026-09-10 新增，节点 `4806:20805`）：32×32 圆形按钮，圆角 16（`Components/Control-m` 尺寸 token），内边距 4，背景 `Background/WT_30`（半透明白，rgba(255,255,255,.30)，适合叠在图片/渐变内容上）；图标 `icf_Arrow_left` / `icf_Arrow_right`，约 24×24。`state=default` 时容器 50% 透明（常态弱化），`state=active` 时 100% 不透明（hover/focus 态）。**产品已确认（2026-09-10）：走马灯默认展示左右箭头，空闲时用 default 态，鼠标悬停/键盘聚焦时切到 active 态。** 若产品需要左右箭头导航，应优先使用这个原生组件，而不是再拼装通用 Button/Icon。Disabled、Autoplay 仍没有对应的视觉 variant，这两项仍不得伪造为设计库原生变体。**2026-09-15（CAR-008）：此前该组件只停留在文档记录层面，现已落地为共享 CSS 类 `.gj-carousel-arrow`（`.is-left`/`.is-right` 控制左右位置；`:hover`/`:focus-visible` 或文档专用类 `.is-active` 切到 100% 不透明；`:disabled` 用独立的禁用透明度，不借用 default/active 语义），组件预览页新增「导航箭头」小节展示三态，并已同步到唯一实际使用走马灯的业务模式页 `preview/patterns/dashboard.html`（原为页面私有拼装的深色小图标按钮，现改用原生规格）。**
- 宽度随容器适配，默认高度 160px；业务可覆盖高度，但同一 Carousel 内所有 slide 必须等高，避免切换时页面跳动。
- `prefers-reduced-motion: reduce` 下取消位移动画和自动播放。


## 使用规则补充（Figma 使用说明，2026-09-10，来源节点 `4806:20708`）

#### 典型构成

- 幻灯片项：每一屏展示的内容（图片、卡片、文字）。
- 导航箭头：左右切换（见上方 `Carousel_item_arrows` 组件）。
- 指示器：圆点或线条，标示当前位置和总数。
- 自动播放控制：播放/暂停。

#### 选用规则

**什么时候不该用**：
- 需要用户主动获取信息时：如果内容重要，就不应该把它藏在一个需要等待或点击才能看到的轮播里。有研究显示，只有约 1% 的用户会点击轮播图，而这 1% 中又有 84% 只点击了第一张。
- 希望突出核心信息时：轮播会将所有内容"民主化"，反而导致没有重点。A/B 测试表明，一张静态图片的点击率（40%）可以远超轮播（2%）。

**什么时候可以考虑用**：
- 一组平级的、非核心的展示型内容：例如官网首页的氛围图、产品介绍页的卡片，它们用于营造视觉感受，而非承载必须被用户获取的关键信息。
- 空间极其有限，且内容有明确先后顺序：例如一个狭小的卡片区域，需要展示多个版本的产品图。
- 如果确定使用，数量必须严格控制：建议轮播项控制在 3 到 5 个之间。超过这个数量，用户几乎不会看完，反而会感到厌烦。

#### 交互规则（Figma 原文）

| 规则维度 | 具体要求 | 原因 |
|---|---|---|
| 自动播放 | 默认关闭，或提供明显的暂停按钮。如果开启，鼠标悬停时必须暂停 | 自动播放会干扰用户阅读，并给认知障碍用户带来困扰 |
| 导航控件 | 必须提供明确的左右箭头 | 箭头是用户主动控制走马灯的主要方式，不应隐藏 |
| 指示器 | 指示点/线应清晰可辨，当前项与未选中项对比明显 | 这是用户判断当前位置和数量的唯一线索 |
| 切换方式 | 支持点击箭头和点击指示器切换。如果内容可点击，需确保点击区域不与切换手势冲突 | 桌面端以鼠标操作为主，点击是最直接的交互；拖拽（draggable）在桌面端属于非必要功能 |

这份 Figma 说明把"必须提供明确的左右箭头"列为导航控件的硬性要求，与既有规则里"箭头是可选组合件"的表述不完全一致——产品已于 2026-09-10 确认按 Figma 说明执行：箭头默认展示，不再是可选叠加件。

#### 宽度适配（按所在层级）

| 所在层级 | 推荐宽度 | 原因 |
|---|---|---|
| 全屏英雄区 | 通栏 | 首页首屏大图，撑满视口，但内部内容仍受最大宽度约束 |
| 内容区英雄区 | 与内容区同宽，常见 1200px / 1440px | 最常见的做法，和下方内容对齐 |
| 内容区内的模块 | 100%（占满父容器） | 例如文章详情页顶部的相关推荐轮播 |
| 卡片/侧栏内 | 100%（父容器宽度内可用区域） | 宽度由卡片或侧栏和其内边距决定 |

桌面端/网页端走马灯的宽度核心原则：它通常不是全屏通栏，而是受内容区约束的固定或自适应容器，具体取决于它放在页面的哪一层。
