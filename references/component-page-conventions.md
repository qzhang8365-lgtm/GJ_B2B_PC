# 组件规范页面制作约束

本文件约束规范网站的展示层，不覆盖组件自身的 Figma 真值、Schema、Token 或运行时契约。优化目标是让用户按“理解结构 → 查看类型 → 对比状态 → 操作组件 → 查阅规则”的顺序快速获得信息。

## 顶部导航条

- Figma 源文件入口挂在 `preview/index.html`（组件交互验收工作台）**已有的** `<header class="topbar">` 上，不在单个组件规范页里另起一行/一条新导航条。`preview/index.html` 本身是一个带侧边栏导航的壳应用，每个组件规范页是通过 `<iframe class="content-frame">` 被加载进壳应用的 `.content` 区域的；如果在被 iframe 加载的子页面里再叠一条自己的顶部条，会在壳应用真实顶部条下面出现一条视觉重复的「第二条顶部条」（2026-09-16 用户截图指出这个问题：`.docs-topbar` 品牌名/Figma 按钮与壳应用已有的品牌名/面包屑挤成两层）。
- 具体做法：`.topbar-figma` 链接（指向设计真值主文件 `https://www.figma.com/design/8b01I1e3TzH1IhYlr3tJzd`，新标签页打开）插入在 `preview/index.html` 内 `<header class="topbar">` 的 `.topbar-spacer` 之后、`</header>` 之前，随壳应用已有的 `.status` 同源样式定义在同一个内联 `<style>` 块里；窄屏（`max-width:760px`）媒体查询里和 `.status` 一起隐藏，不占用移动端顶部条的有限宽度。
- 不加 GitHub 图标：本仓库虽在 GitHub 上是公开仓库，但内容属于公司内部设计资产（见根目录 `README.md`），顶部导航是高可见位置，不适合引导访问者点进代码仓库。
- 单个组件规范页（`preview/<组件名>/index.html`）本身不需要、也不应该再有自己的顶部导航条——这些页面的「壳」入口只有 `preview/index.html` 一处，直接单独打开某个组件页面（不经过壳应用）本来就是非常规访问路径，不需要为此专门补一份平级的页面内导航。

## 信息架构与内容顺序

- 页面采用连续纵向阅读流，推荐顺序为：标题与简介 → 主要类型/基础用法 → 尺寸 → 状态 → 关键能力 → 交互演示 → 规格与选用规则。组成结构是条件模块，不是固定首屏章节。
- 章节必须按组件特点取舍，不为套模板制造空板块；同一规则只在最适合的位置出现一次。
- 删除重复标题、过程性说明和无实际价值的代码展示。页面只说明组件本身，不出现“来自 Figma”“只读不修改设计文件”等内部工作描述。
- 已有独立规范页的依赖组件只说明依赖关系与选用条件，不在当前页面重新实现。例如 Selector 复用 Dropdown、Form 组合 Input/Selector/DatePicker。

## 容器层级与视觉节奏

- 一级白色内容容器使用 12px 圆角，原则上无描边；二级展示面板使用 8px；更内层标签与局部文档控件使用 4px，真实组件仍以自身 Token 为准。
- 优先通过背景、留白、章节间距和必要的分割线建立层级，避免卡片套卡片和重复边框。
- 章节之间保持统一的纵向间距与分割节奏；标题、说明和示例靠近所属内容，相同层级保持标题基线、内容起点和卡片高度对齐。
- 示例区必须保留足够内边距；收窄时优先换行或重排，不通过拉伸间距填满一行。

## 字体层级

- 页面标题、章节标题、示例标题、分类标签、Form Label 和说明文字必须形成清晰层级。
- 所有组件与基础规范页的页头只使用一套标题基座：Eyebrow 为 13/20 Semibold，与标题间距 8px；桌面端 H1 为 28/40 Semibold，紧凑宽度为 26/36；简介为 14/22 Regular，最大宽度 920px。新页使用 `.docs-page-head` / `.docs-eyebrow`；旧页 `.intro` / `.eyebrow` 只作迁移兼容，不得再定义另一套字号、行高或间距。
- “默认状态”“必填状态”等文档分类标签不得与真实组件 Label 使用完全相同的字形；通过字号、字重或次级文字色区分。
- 正文原则上不小于 14px；变量名、英文属性和值、辅助标记可使用 12px。说明使用次级文字色，辅助信息使用三级文字色。
- 大号和粗体只用于标题或必要强调，不用粗体补偿层级混乱。

## 组成结构示意

- 仅当组件由多个职责独立的区域、槽位或子组件组成，并且结构关系会影响选用、实现或交互时，才设置独立的“组成结构”章节。
- Badge、Button、Divider、Avatar、Empty、Tag、Radio、Checkbox 等结构直观的原子组件不单独展示组成结构；Steps、Tabs、Upload 等可把简单构成并入规格表。
- Form、Table、Selector、Dropdown、Cascader、Navbar 等复合组件可保留组成结构，但不必机械放在首屏；应根据用户理解路径决定位置。
- 结构示意必须解释组件构成，例如 `Component = Trigger + Content + Indicator`，不能只作为装饰。
- 主体组件使用 `docs-structure-primary` 品牌蓝和反白文字，组成部分使用白色卡片；结构项包含短名称和一句作用说明。
- 横向卡片平均分配宽度并对齐；空间不足时整体切换为纵向排列，连接符跟随排列方向。

## 组件示例与状态

- 示例必须优先调用共享组件基座与全局 Token。页面私有 CSS 只负责文档布局，不重新定义真实组件的尺寸、颜色、状态或图标。
- 图标使用已上传的组件库资源和共享图标类，不使用字符、Emoji、临时 SVG 或 CSS 图形替代。
- 同一操作层级保持同一组件尺寸，默认优先 Medium；只有明确展示尺寸差异时才混用 Small/Medium/Large。
- 示例不得溢出容器。宽组件使用 `max-width:100%`、内部换行、局部横向滚动或断点重排，不直接裁掉内容。
- Default、Hover、Focused、Selected、Error、Disabled 等互斥状态必须准确区分；静态状态示意不写入虚假的 ARIA 状态，ARIA 只服务真实交互。

## 交互演示

- 默认采用左侧组件、右侧属性控制的 3:2 布局；宽度不足时切换为上下布局，属性区不得覆盖示例区。
- 左侧只保留组件和必要上下文；右侧字段优先两列，只保留帮助理解组件的关键属性。
- 交互必须调用共享运行时，不复制临时组件逻辑。每次修改都检查旧脚本、重复初始化、互斥状态、展示值同步、Placeholder/选项边界、Disabled、键盘与焦点行为。

## 规则与表格

- 规格、规则、边界与禁用场景优先整理为“主题／推荐做法／边界与避免”三列表格。
- 使用共享规范表格；表头与普通单行单元格默认 48px，高度需要换行时自然增加，表头使用统一灰色背景。
- 表格外层允许局部横向滚动，文字不得被固定列或遮罩覆盖；单个单元格避免堆入长段落。
- 规则除数值外还应说明何时使用、何时不用以及特殊场景如何处理。

## 响应式与宽度

- 桌面端规范页仍需覆盖窄浏览器窗口。普通控件保持合理稳定宽度，不默认 Fill Width。
- 多个筛选控件靠左排列，收窄后按固定间距换行；不因每行数量减少而放大剩余间距。
- 推荐宽度和最小宽度应进入组件规范。Table、Cascader、长列表等宽内容只在自身容器滚动，不推动整页产生异常横向滚动。
- 窄屏至少检查标题换行、组件溢出、卡片覆盖、属性区重排、表格可读性和浮层视口边界。

## 完成检查

- 检查共享 Token、共享基座和 Skill/Schema 规则是否一致。
- 检查页面私有组件样式、旧脚本、重复初始化和无效逻辑是否已清理。
- 检查溢出、遮挡、错位、尺寸混用、图标尺寸/热区/对齐和宽窄屏表现。
- 检查互斥状态、Placeholder、空值、禁用值、已选值、键盘与焦点行为。
- 检查表头、行高、固定列、背景和局部滚动是否统一。

## 图标资源

- 页面中的图标必须优先引用 `assets/icons/iconfont/` 中已经上传的组件库资源。
- General 通用图标引用普通 SVG / Icon Font 资源；复杂渐变效果图标引用对应 Effect SVG 资源。
- 不使用 Emoji、Unicode 符号、临时 CSS 图形或自行绘制的替代图标。
- 图标默认跟随相邻文字颜色；需要继承颜色时，可将组件库 SVG 用作 CSS mask，但资源来源仍必须是已上传图标库。
- 只有组件库确实不存在所需图标时，才提出缺失项并等待补充，不自行创造近似图标。

## 组件基座与死代码

- 预览页的静态展示区和交互 Demo 区，都必须使用共享 `assets/styles/gj-b2b-components.css` 里的标准组件类（`gj-modal`、`gj-modal-close`、`gj-btn`、`gj-form-*` 等）渲染，不允许另起一套仅供该页面使用的 mock 结构（例如自定义的 `.icon-button`、`.modal-window`、`.btn` 等）——这类临时结构一旦被真实组件类替换后忘记清理，会在页面内嵌 `<style>` 里留下死代码，增加后续误改的风险（2026-09-11 起，MDL-010 首次系统性核查并清理）。
- 迁移或重构某个预览页的展示结构后，必须回头检查该页 `<style>` 里是否还有不再被任何 `class="..."`（含 JS 拼接的模板字符串）引用的选择器；复合选择器（如 `.a,.b{...}`）要逐项核对，只删除全部子选择器都确认无引用的规则，混有真实类的要保留但裁掉死亡分支，不整条删除。
- 不确定某个类是否还在用时，先在真实 HTML/JS 里搜索确认，不凭选择器名称是否眼熟就删除或保留。

## 展示背景选择

- 默认使用白色展示背景（`docs-surface-white`）：适合组件自身带灰色填充、或默认态就是深色/强对比色的组件（如 Tabs、Selector、Input、灰底按钮组、卡片）。
- 灰色背景（不带修饰类的 `docs-stage` 默认态，或显式 `docs-surface-gray`）按需使用：主要用于展示白色或近似白色填充的组件——例如 Checkbox/Radio 默认态是白底 + 描边，直接放在白色画布上会被边框以外的部分"吃掉"，需要灰色画布制造至少一级明度差；同理适用于阴影、悬浮卡片，以及其他需要与页面白底区分的内容。
- 深色或透明组件使用专用对比背景（`docs-surface-dark`）：例如 Ghost 按钮、白色半透明填充、Glass 效果，选择能清楚体现边界的深色或图案背景。
- 展示背景与组件默认填充之间必须保持至少一级明度差，不能让组件容器与演示画布融为一体；两者恰好都是白色时，用 `docs-surface-white` 自带的 1px 边框而不是改变背景色来建立边界。
- 判断明度差时要看「实际相邻的两层」，不要只按组件类型套用固定背景色：如果演示区本身已经用一张卡片（sample-card、combo-card、interaction-stage、controls 之类的私有容器）承担了「白色/灰色展示面」的角色，外层 docs-stage 该选什么色要看这张卡片的颜色，而不是看卡片里最终渲染的组件颜色——卡片是白色就配灰色画布，卡片是灰色就配白色画布，避免同色卡片叠同色画布导致内外边界消失（Input 页面 INP-010 就是先套用了「Input 默认应配白色画布」的字面规则、忽略了页面已有白色卡片这一层，导致两层白色叠在一起，后来改回灰色画布才修正）。
- 交互演示区的属性控制面板（`.controls`）固定使用 `docs-surface-white`，与左侧 `.lab` 演示舞台的背景选择规则相互独立。
- 背景只服务于辨认组件本身，不应暗示组件在实际业务页面中必须运行于该背景上。

## 展示区的网格布局

- 一组并排展示的变体（尺寸、状态、类型……）优先用显式 `display:grid` 加固定 `grid-template-columns` 列数，不要用 `display:flex;flex-wrap:wrap` 让浏览器按容器宽度自然换行——flex-wrap 换行的结果随视口宽度变化，同一组内容在 1280px 和 1000px 下可能是不同的换行方式，看起来「参差不齐」（Switch/DatePicker 的 SWI-005/DTP-013 曾因此被用户反馈「矩阵不整齐」）。
- 选列数时优先让列数能整除卡片数（例如 6 个状态用 3 列或 2 列，不用 4 列留一个孤项）；确实除不尽、必须有孤项时，让它落在明确的网格末尾（比如 2 列网格最后一行只有 1 项），而不是因为容器宽度不够才被动换行到下一行——同一份 HTML 在不同宽度下应该呈现同一个结构，只在预设的窄屏断点才整体切换列数。
- 如果一组展示天然是两个维度的组合（例如尺寸 × 状态），做成真正的表格（行 = 一个维度，列 = 另一个维度），不要拆成一串卡片再指望它们自然换行拼成矩阵——像 Input 的「尺寸与状态」`state-table` 那样显式表达两个维度，比 8 张卡片挤成 2 行 4 列更可靠，也是用户认可的参照样式。
- 单个变体宽度差异很大时（例如 DatePicker 的单日期面板 280px vs 范围面板 560px），用显式的 `grid-column:1/-1`（或等效 span）让宽项跨列，而不是让 flex-wrap 按剩余空间随意决定它跟谁同行。

## 交互脚本与元素显隐

- 不要用 `el.hidden = true/false`（或 `hidden` 属性）来控制共享组件基座类（如 `gj-btn`、`gj-btn-primary` 等）元素的显隐——这些类自身在 `gj-b2b-components.css` 里显式声明了 `display:inline-flex` 之类的值，是作者样式表规则，会覆盖浏览器对 `[hidden]` 属性的默认 `display:none`（同优先级下作者样式表本就压过 UA 样式表，与选择器权重无关），导致元素设置 `hidden` 后实际仍然可见、照常占位（Search 页面 SEA-005 曾用 Playwright 的 `getComputedStyle` 实测复现：`button.hidden=true` 后 `display` 仍是 `flex`）。
- 正确做法是直接控制 `el.style.display`（例如 `el.style.display = condition ? 'none' : ''`），或者切换一个页面私有的、优先级更高的显隐类；`hidden` 属性只适用于没有被组件基座显式设置 `display` 的普通容器元素。
- 这是一个可能残留在其他预览页的共性问题（例如 Upload/Toast 页面也用 `.hidden` 切换 `gj-btn` 按钮），后续任何页面被审计到交互脚本时，应顺带检查是否存在同样的写法。
