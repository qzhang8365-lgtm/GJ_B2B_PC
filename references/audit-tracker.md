# 设计系统待确认项跟踪表

本表是本地 Skill 中所有开放审计项的唯一总览入口。各 `audit.md` 保留证据、节点和历史细节；新增、关闭或拆分待确认项时，必须同步更新本表。不得根据本表的简述覆盖来源文件或 Figma 真值。

## 状态与优先级

- 状态：`待设计确认`、`待 Figma 复查`、`待资产补齐`、`待前端验证`、`已关闭`。
- 优先级：P1 会导致组件语义或实现错误；P2 影响一致性、迁移或完整抽取；P3 属于命名、描述和维护性优化。
- 本表默认只列开放项；关闭时保留原行并改为 `已关闭`，同时补充结论与日期。
- **画板 symbol 数明显多于 inventory 登记数时，先看 `components/extraction-plan.md`「母版、子变体与 inventory 计数」第 6 点**：部分 Figma 页面在母版旁边另加了「规则说明」画板并插入子组件实例做示意，AI 容易把这些示意实例误计成新 variant。2026-09-09 用户明确指出这是已知会反复出现的成因，不是逐个组件的偶发问题；排查此类「待 inventory 复查」项时先核对是否命中这个模式，再考虑其他原因。

## 维护规则

1. 每个开放项使用稳定 ID；不要因改写文案重新编号。
2. 来源 audit 增加或关闭问题时，同一提交必须更新本表。
3. `待设计确认` 不得由代码实现自行关闭；`待 Figma 复查` 必须记录节点和核验结果；`待前端验证` 必须记录可复现的浏览器或构建结果。
4. 关闭时保留记录，状态改为 `已关闭`，在“下一步 / 关闭条件”中写明结论、日期和被修改的资产。
5. 全量组件抽取任务关闭后，应同步更新对应 `schema.json`、`mapping.json`、`audit.md` 和 `inventory.json` 状态。
6. 数 inventory 时先认母版再数子变体：`sets` 是组件集母版，`variants` 是母版下的 `属性=值` 子组件。禁止用画板可见 symbol 数去对 `sets`，也禁止仅因 MCP 把组件集标成 frame 就开「根 ID 未返回」。详见 `extraction-plan.md`「母版、子变体与 inventory 计数」。
