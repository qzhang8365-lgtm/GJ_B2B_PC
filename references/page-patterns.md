# PC 端 B 端页面模式

独立可视化入口：`../preview/patterns/index.html`。页面模式与组件工作台 `../preview/index.html` 分离维护；前者用于查看完整页面组合，后者只用于检索基础规范与组件。

五个模板共用同一个响应式页面画布：根容器 `width:100%`、`max-width:1244px`、`margin-inline:auto`，四边页面边距固定为 `20px`。1244px 外宽减去左右边距后得到 Figma 样板的 1204px 内容宽；窄于上限时随容器收缩，宽于上限时保持居中。断点不得修改页面边距或最大宽度，只负责栅格换列、模块堆叠、筛选换行和局部滚动；1440px 是设计基准，不是固定页面宽度。卡片自身的 20px 内边距属于组件内容间距，不与页面边距混用。

页面模式中的一级背景卡片默认使用 `Background/Container` 且不加描边，通过页面灰背景、卡片间距和圆角形成层级，减少大面积浅灰框线带来的束缚感。只有同色背景无法分层、卡片本身具有选择或交互边界，或具体设计稿明确要求时，才允许显式增加语义描边；内部表格、表单控件及二、三级模块继续遵循各自组件边框规则。

统一栅格降级：`pc.sm` 下筛选区允许换行、三列表单降为两列，表格保持组件最小内容宽并在自身容器横向滚动；小于 1280px 属于非承诺视口，但必须保证核心操作可访问，详情与指标降为两列、工作台降为单列；小于 768px 仅作为预览和应急访问，表单、详情和指标降为单列，宽图表局部横向滚动。禁止各模板另设 `960/1100/640` 等私有断点。

本文件提供最小页面组合约束，用于把组件组织成完整界面。它定义信息结构，不规定真实前端组件库 API。若具体设计稿已有明确结构，以设计稿为准。

所有可视化页面必须加载 `../assets/styles/gj-b2b-components.css`，并优先使用其中从组件预览归并出的 `gj-*` 静态组件类。已有组件能够覆盖需求时，不使用临时 HTML 或页面私有样式仿制；确有新增业务能力时可以补充组合或扩展实现，并把可复用部分维护到共享组件层。

## 通用页面骨架

常规页面按需由以下区域组成：全局导航、页面标题与面包屑、上下文或摘要、筛选与操作、主内容、分页或后续操作、反馈层。不要为了凑齐结构加入没有业务价值的区域。

- 页面级主操作通常放在标题区右侧或主内容操作栏右侧，同一区域原则上只有一个最高优先级操作。
- 同一视觉层级、同一操作组或同一表单行的交互组件必须统一尺寸档位与可见高度。页面组合在父级确定尺寸并传递给子组件；不要让相邻控件各自使用默认值而形成 Small、Medium、Large 混排。表格行级操作、分页等独立紧凑层级按各自组件规范处理。
- 筛选、批量操作和表格属于同一任务流时，应保持空间与状态关联。
- 页面首次进入、刷新、局部加载、空数据、查询无结果、请求失败和无权限应按实际业务区分。
- 表格和复杂表单在窄视口下优先保持任务可完成，再决定换行、隐藏非核心信息或横向滚动。

## 模式一：查询列表

可视化参考：`../preview/patterns/search-list.html`。

适用于客户、账户、产品、任务、订单和审批等对象集合。

结构：页面标题/面包屑 → 筛选区 → 操作栏 → 数据表格或列表 → 分页。

- 高频条件直接展示，低频条件收纳到“更多筛选”；筛选项过多时允许换行。
- 查询、重置与筛选条件保持邻近；查询条件改变但尚未提交时，不悄然改变列表数据。
- 批量操作只有在选择数据后才可用，并明确已选数量及取消选择方式。
- 行级操作数量较多时保留高频操作，其余收纳，不让操作列无限变宽。
- 操作列中的文字操作使用 Small Text Button，相邻按钮保持 8px 净间距；图标操作使用 16px 图标和 12px 间距。
- 区分“系统没有数据”和“当前筛选无结果”，后者应提供清除筛选入口。
- 表格列超过可用宽度时固定关键识别列和操作列，其余允许横向滚动或按优先级隐藏。
- 常用条件之外的低频条件由“更多筛选”展开；提交查询后用可移除标签呈现已生效条件。编辑控件但未点击查询时，列表仍保持上一次提交结果。
- 列表应按业务需要覆盖分类、流程状态、负责人、日期和关键词等不同条件类型，但不得为了展示组件而加入无业务意义的筛选项。
- 可排序列必须明确当前升降序，单列排序时同一时间只有一个有效排序状态；行级低频操作收纳到互斥的 Dropdown。
- 选择数据后在表格邻近位置显示批量操作栏、已选数量和取消选择；批量删除等不可逆操作必须经过确认，完成后用 Toast 反馈结果。复制、删除完成等短时反馈使用 Black Toast，出现在页面底部居中；保存/提交类结果用 Float 或 Transparent，出现在顶部居中。
- 筛选无结果时隐藏表格和分页，展示“当前筛选无结果”的 Empty，并提供清除筛选入口；不能与系统从未产生数据的空状态混用。
- 每页条数使用稳定的预设选项，不允许任意输入；跳页输入将值限制在有效页码范围内，省略号不可点击。

真实组合样板：Figma 节点 `4607:27917`（sample-3-查询与列表）。默认组合参数如下：

- 筛选卡片内边距为水平 20px、垂直 16px，圆角 12px；两行筛选内容间距 16px。
- 筛选项采用横向 Form Item：Label 宽 80px、Medium 高 32px；Select 宽 160px，Search 宽 240px。
- 第一行筛选项间距 20px；第二行搜索项与按钮组间距 16px；查询与重置按钮间距 8px。
- 筛选项采用左对齐的可换行流式布局，不使用 `space-between` 或等分 Fill 栅格。普通 Label + Select/Input 组合宽 240px，Search 组合宽 320px；浏览器收窄时只减少每行项目数并保持既定间距，不拉伸控件或放大项目间距填满一行。
- 极窄预览下 Select 仍保持 160px 的可读宽度并靠左排列，不自动撑满整行；只有日期范围等确实无法横向容纳的复合条件可将标签移至控件上方，其内部控件仍保持稳定宽度。
- 查询使用 Primary Medium，重置使用 Secondary Medium；两者均可使用 16px 左图标。
- 筛选区控件与操作按钮默认统一使用 Medium；日期范围必须优先组合已维护的 Medium DatePicker 范围触发器和日历面板，不使用两个原生日期输入替代。分页每页条数和表格行级操作可按各自组件规则使用 Small，不视为同一按钮组的尺寸混用。
- 列表卡片内边距 20px，工具按钮组与表格、表格与分页之间的垂直间距均为 20px。
- 列表工具栏将标题放左侧、同级操作放右侧并允许整体换行；同一 Medium 按钮组保持 8px 间距和一致高度。一般操作使用 Tertiary Medium，页面或区域主操作只保留一个 Primary Medium。
- 表格优先直接组合共享 Table，并使用默认 Medium：表头、内容行及固定操作列统一为 48px 高、水平内边距 16px；表头为中文 14/22 Semibold、`Text/Secondary`，所有表头单元格统一使用 `Table/head_bg`。只有用户明确要求紧凑或疏松时才整体切换为 Small 或 Large，不允许局部单元格混用尺寸。
- 可排序列使用 Table 组件规定的 `icf_Arrow_caret.svg` 及排序状态，不从通用图标中选择近似资源，也不在页面样式中重新绘制排序图标。
- 表格主字段不是操作按钮：使用中文 14/22 Regular 和 `Text/Primary`，可点击时仅在 Hover 变为 `Text/blue`。只有末列“查看、编辑、更多”等行级操作使用 Small Text Button。
- 分页使用 Default 32px，页码间距 4px；每页条数控件为 Small 24px，并与总数、分页器右对齐。
- 完整样板还应验证：查询中按钮状态、全选/部分选择联动、状态 Tag、日期范围、排序、行级更多菜单、批量状态修改、删除确认、复制/完成 Toast、查询无结果和分页边界。

## 模式二：新建或编辑表单

可视化参考：`../preview/patterns/form-edit.html`。

适用于录入、配置和修改业务对象。

结构：页面标题/返回 → 表单分组 → 辅助说明或关联信息 → 提交操作区。

- 字段按业务任务分组，不按数据库字段顺序机械排列。
- 标签、控件和帮助信息在同一页面保持统一对齐；长表单使用分组标题或锚点，不默认拆成多个步骤。
- 多列表单的列和字段容器必须允许收缩；同一行控件顶部对齐且默认占满列宽。浏览器缩放或容器变窄时按断点减少列数，不允许 Input、Selector 或 Textarea 溢出卡片。
- 底部按钮组不使用独立白色卡片或 Sticky 背景栏。本模板包含多张填写卡片，因此按钮组使用透明容器，放在最后一张卡片之后并右对齐；单卡片表单则放入卡片内部右下侧。
- 必填、格式、范围和跨字段校验应在最接近问题的位置反馈；提交失败后定位首个错误。
- 主提交操作名称应表达结果，如“创建客户”或“保存配置”，避免在关键流程中只写“确定”。
- 离开包含未保存修改的页面前，根据业务风险提示用户。
- 只读字段与禁用字段语义不同：只读表示可查看不可改，禁用还应说明不可操作原因。

## 模式三：对象详情

可视化参考：`../preview/patterns/object-detail.html`。

真实组合样板：Figma 节点 `4651:21082`（Sample-客户详情）。模板内容区不重复实现宿主系统的侧栏和顶栏。

适用于查看单一客户、账户、产品、任务或审批对象。

结构：对象标题与关键状态 → 主要操作 → 摘要信息 → 分组详情 → 关联列表、记录或时间线。

- 首屏优先展示识别对象和完成任务所需的信息，不把所有字段做成同等权重卡片。
- 状态与主要操作保持因果一致；不可用操作需要隐藏或禁用时遵循权限与可解释性要求。
- 信息较少时使用分组描述布局，信息或关系复杂时才使用 Tabs。
- 关联记录沿用查询列表模式；变更历史或流程记录优先使用时间线。
- 危险操作与普通编辑操作分离，并在执行前说明影响范围。
- 标题区高 88px、水平内边距 20px；对象名称使用中文 18/26 Semibold，状态使用 Regular Tag，右侧按钮间距 8px。
- 信息卡宽 1204px、高 264px，内边距与区块间距均为 20px、圆角 12px；结构依次为 Tabs、四列摘要、四列两行基础信息。
- Tabs 仅包含“基本信息、关联账户、变更历史”，标签间距 24px；当前项为 Highlight 状态。由于 Tabs 是卡片首个元素，使用卡片顶部布局变体压缩容器占位高度，同时保持 Tab 项标准点击高度。
- 信息项标签和值均使用中文 14/22 Regular，标签使用 `Text/Tertiary`、值使用 `Text/Primary`，标签和值间距 4px；列间距 24px、详情行间距 16px。
- 近期业务记录卡高 228px，标题为中文 16/24 Semibold；表格使用 Medium，列顺序为业务类型、业务单号、经办人、当前节点、更新时间、操作。

## 模式四：概览与工作台

可视化参考：`../preview/patterns/dashboard.html`。

真实组合样板：Figma 节点 `4653:22581`。模板必须复用共享 Metric、Chart、DatePicker、Table、Tag 和 Button；页面样式只负责卡片栅格与模块编排，不得用页面级 CSS 重绘柱、坐标轴、日期单元格或交互状态。

适用于用户需要同时判断状态、发现异常并进入后续任务的首页或业务看板。

结构：范围与时间上下文 → 核心指标 → 异常和待办 → 趋势或分布 → 明细入口。

- 指标数量服从决策任务，不为了填满栅格增加无价值数字。
- 同一指标跨卡片和图表保持名称、单位、精度、颜色及时间范围一致。
- 图表必须提供标题、单位、时间范围和必要图例；颜色不作为唯一的信息区分手段。
- 异常、风险和待办优先于装饰性趋势；卡片应有明确的点击结果或保持不可点击。
- 数据加载失败时按模块反馈，避免单个次要模块导致整个工作台不可用。
- 样板内容宽 1204px：顶部 4 张等宽 Metric 卡；第二行左侧为约 2/3 宽的正负柱状图，右侧为约 1/3 宽的单月 DatePicker 面板与三条待办摘要；第三行为全宽异常表格。模块间距 16px，卡片内边距 20px、圆角 12px。
- 顶部数据卡引用 Figma 节点 `4653:22752` 的 `Metric_card_withgraph` 结构：卡高 122px、内边距 20px、内容区高 82px并垂直均分；标签使用中文 14/22 Regular 与 `Text/Secondary`，数值使用 GJType Bold 24/32 与 `Text/Primary`，比较标签使用中文 12/18 Regular 与 `Text/Primary`。趋势值使用中文 12/18 Semibold，Rise 为错误红、Decline 为成功绿；14px 趋势图标必须来自图标库并通过 `currentColor` 与文字保持同色。
- 正负柱状图使用 Chart 的 Positive / Negative · Vertical 变体：正负值共用明确零基线，正值使用 `Chart/CH01`、负值使用 `Chart/CH02`，柱宽保持 12–40px、圆角 4px；必须显示单位、横纵轴刻度与数据标签，不能用普通 `div` 高度模拟柱体。
- 待办日历必须引用 DatePicker 的完整单月面板及 Date Item 状态，不得以普通网格伪造；当前日期、选中日期、跨月日期和通知点分别使用组件定义状态。
- 工作台同一栅格行不得分别写死左右卡片高度。待办卡由日历和任务条目自然撑高，趋势卡通过 Grid 拉伸到相同高度；图表画布再在卡片剩余空间内自适应，避免内容溢出或两侧底边错位。
- 正负柱状图的 `<svg>` 禁止使用 `preserveAspectRatio="none"`：`preview/patterns/dashboard.html` 曾经这样写，容器宽高比与 `viewBox`（760×300）不一致时图内数值、坐标轴文字会被非等比拉伸变形；已改回默认的 `xMidYMid meet`（2026-09-14，同步写入 SKILL.md 全局硬规则）。
- 待办日历的翻页按钮必须复用 `assets/scripts/gj-date-picker.js`（`header()` 函数）里实际渲染的图标 span（`.gj-date-panel-icon` + 对应 `icf_Arrow_*` 资源），不得手写 `«`/`‹`/`›`/`»` 等占位文字字符——`preview/patterns/dashboard.html` 曾经这样写，已改成引用真实图标（2026-09-14）。

## 模式五：分步任务

可视化参考：`../preview/patterns/step-task.html`。

真实组合样板：Figma 节点 `4645:19059`。页面模板必须优先复用共享 Steps、Alert、Table、Tag 和 Button，不在页面样式中重绘组件视觉。

仅用于存在明确顺序、后续步骤依赖前一步结果，或中间结果需要确认的复杂任务。

结构：任务标题 → 步骤状态 → 当前步骤内容 → 上一步/下一步或提交操作 → 完成结果。

- 简单表单不要为了视觉形式拆成步骤。
- 明确当前、完成、未开始和失败状态；用户返回前一步时保留已录入内容。
- 最终提交前汇总不可逆或高风险信息；完成页说明结果与下一步入口。
- 中途退出、保存草稿和失败恢复规则由业务风险决定，未知时标记待确认。
- 样板内容卡片内边距 20px、圆角 12px，最小高度 749px；Steps 区域高 76px、拉满内容宽 1160px。全宽时两侧各留 48px，步骤等距分布；Serial / Point 与步骤名居中对齐，步骤圆点 32px，步骤名使用中文 16/24 Semibold。
- 当前 Figma 实例为第 1 步 `process`、其余为 `wait`；即使当前内容示例标题为“上传开户材料”，也不得擅自改写实例状态。
- 当前步骤标题与提示条的垂直间距各 16px；提示条使用 Info 状态，高 48px；图标必须引用图标资源并继承组件状态色。
- 材料表格使用 Medium，表头与内容行均为 48px；状态使用 Small Tag；表格操作使用 24px 文本按钮，默认 `Text/Secondary`、悬停 `Text/Blue`。
- 底部操作左侧为 Tertiary Medium“上一步”，右侧为 Tertiary Medium“保存草稿”和禁用态 Primary Medium“下一步”，按钮间距 8px。

## 选择方法

- 核心任务是查找和批量处理对象：查询列表。
- 核心任务是录入或配置单个对象：新建/编辑表单。
- 核心任务是理解并操作一个对象：对象详情。
- 核心任务是跨对象监控和分流任务：概览/工作台。
- 核心任务具有不可省略的顺序依赖：分步任务。

一个页面可以组合模式，例如“详情页中的关联记录”复用查询列表，但必须有一个主模式决定页面信息优先级。
